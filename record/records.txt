What is Postman?

Postman is simply a program that lets us talk to and test our backend API.

So you've now successfully done both:

GET /tasks  → get tasks
POST /tasks → create a tasks

What actually happened?

When you clicked Send, Postman sent this to your backend:

   ▼

   │ sends JSON response

Once we add PostgreSQL, we'll start replacing the hard-coded tasks with real persistent data.

Now we're going to make the important change: instead of returning the fake tasks we wrote inside server.js, we'll make /tasks fetch the tasks from PostgreSQL.

Why this is a big step

Previously, those tasks were written directly in JavaScript.

Now the process is:

Browser
   ↓
GET /tasks
   ↓
Express
   ↓
pool.query("SELECT * FROM tasks")
   ↓
PostgreSQL
   ↓
3 rows
   ↓
Express
   ↓
Browser

res.json(result.rows);

sends those rows back to your browser as JSON.

Postman
   │
   │ POST /tasks
   │ { "title": "Learn Express" }
   ↓
Express
   ↓
PostgreSQL
   ↓
INSERT INTO tasks
   ↓
Task permanently stored

You should now see 4 tasks, including:

Learn Express

This proves that:

Postman → API → PostgreSQL → API → Browser

is working.
$1 → "Learn Express"

This is called a parameterized query. It's the proper way to send values to SQL instead of directly joining user input into the SQL string.

What are we storing?

Our table will look like:

id	name	email	password	created_at
1	Ruthwik	user@email.com	encrypted...	...

Notice that the password column will not eventually contain the user's actual password.

We'll use a library called bcrypt to hash passwords.
User enters:
MyPassword123

Database stores:
$2b$10$..............

The response does NOT contain the password. 🔒
